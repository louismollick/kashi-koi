# Breakdowns and decoys plan

Two changes to how the app teaches grammar, replacing the per-line notes.

1. **Breakdown**: an on-demand explanation of one sentence, built up chunk by chunk from dictionary forms. Generated by the server the first time someone with the admin token asks, then cached and shared like song analyses.
2. **Decoys**: each analyzed sentence carries 2 wrong translations made by swapping one short phrase of the right translation. Meaning Match uses them instead of random same-song translations, underlines where the options differ, and shows why the picked decoy is wrong.

Songs without a song analysis keep today's behavior: line-by-line iOS translations, random same-song choices, no breakdowns.

The server database is wiped on deploy. There is no backward compatibility: `schemaVersion` becomes 2 and the phone ignores cached analyses with version 1 (it already drops analyses that fail validation).

## Shared schema (`packages/shared`)

```ts
const decoy = z.strictObject({ from: text, to: text, reason: text });
songAnalysisDraftSchema = z.strictObject({
  title, summary, speaker, addressee,
  lines: z.array(text),
  sentences: z.array(z.strictObject({ start, end, translation: text, decoys: z.array(decoy) })),
  // notes removed
});
songAnalysisSchema = draft.extend({ schemaVersion: z.literal(2), fingerprint, model, createdAt });
```

`validateAnalysis` adds, per sentence:
- exactly 2 decoys
- `from` occurs in `translation`, is shorter than it, and differs from `to`
- the two `from` phrases (first occurrence) are the same span or do not overlap
- both decoy texts (translation with `from` replaced by `to` at its first occurrence) differ from the translation and from each other

```ts
const step = z.strictObject({ japanese: text, reading: z.string(), english: text });
breakdownDraftSchema = z.strictObject({
  chunks: z.array(z.strictObject({ text, steps: z.array(step), note: z.string() })),
});
breakdownSchema = draft.extend({ fingerprint, start: lineIndex, model, createdAt });
validateBreakdown(draft, sentenceText): string[]
```

`validateBreakdown` checks: 1 or more chunks, 1 to 4 steps each, and the chunk texts joined equal the sentence text (the sentence's lines joined) after removing whitespace, punctuation and symbols (`\s`, `\p{P}`, `\p{S}`) from both. `reading` is hiragana or empty.

## Server

- `analyses` table stores the analyzed `lines` too, so a breakdown prompt can include the whole song. New `breakdowns` table keyed by `(fingerprint, start)`. Replacing an analysis deletes its breakdowns. Migrations are regenerated as one fresh initial migration.
- The Codex runner takes a prompt, JSON schema and reasoning effort, so analyses and breakdowns share it. `KASHI_BREAKDOWN_REASONING` defaults to `low`.
- `GET /v1/analyses/:fingerprint/breakdowns/:start`: public. 200 breakdown, 404 when none is cached.
- `POST /v1/analyses/:fingerprint/breakdowns/:start`: admin bearer token. Returns the cached breakdown, or generates one synchronously (validate, one retry with feedback, store, return 200). 404 when there is no analysis or `start` is not a sentence start. 429 on a usage limit. 502 on other generation failures. Concurrent requests for the same key share one generation; at most 2 generations run at once.
- Prompts: `analyzer/prompt.ts` (analysis) and `analyzer/breakdown-prompt.ts` (breakdown).

## Phone

### Choices

```ts
type Choice = { text: string; parts: { text: string; marked: boolean }[]; correct: boolean; reason?: string };
```

`Run.choices` and `ClipReview.choices` become `Record<string, Choice[]>`. Answers are still matched by `text`.
- With decoys: the right translation plus its 2 decoys, shuffled. The marked regions are the distinct `from` spans. Every option marks every region; a decoy's own region holds its `to` text.
- Without decoys (no analysis): today's random same-song translations, each a single unmarked part.

`Sentence` gains `decoys?: Decoy[]`, copied from the analysis by `withSentences`.

### Holding on a miss

- Run: a correct answer keeps the 800 ms beat. A wrong answer while the song is held leaves it held until `continueAfterAnswer()`.
- Clip review: a correct answer auto-advances after 800 ms as today. A wrong answer waits for `nextClip()`.

### Breakdowns

`src/analysis/breakdowns.ts`:
- Non-persisted state keyed `${fingerprint}:${start}`: `loading | ready | failed | missing`.
- `breakdownTarget(songId, sentenceId)` resolves the fingerprint and the first occurrence's start. It returns `undefined` for songs without an analysis.
- `loadBreakdown(songId, sentenceId)`: GET, then POST when the GET returns 404 and a token is set. Without a token, a 404 means `missing`. Calls for the same key share one request.
- `prefetchBreakdown(songId, sentenceId)`: fires quietly after a lost mark and after a wrong answer in a run or clip review, only with a token.
- `useBreakdown(songId, sentenceId)` returns the state for the UI.

### UI

- Listen mode: an EXPLAIN button next to REVIEW LATER for the current sentence, and a long press on any lyric line. Only shown for analyzed songs with the song analysis source selected.
- Quiz and clip review: decoy differences underlined. After a miss, the picked decoy shows its reason, with EXPLAIN and CONTINUE (or NEXT) below the answers.
- Results: each missed sentence gets EXPLAIN.
- `/breakdown?songId&sentenceId`: a sheet with the sentence, its translation, and the chunks.
- Notes are removed everywhere. The summary is one sentence and speaker/addressee are a few words each.
